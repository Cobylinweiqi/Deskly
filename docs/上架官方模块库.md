# 上架 LSPosed 官方模块库（可选）

> 这一篇是给**维护者**看的操作备忘，普通用户不需要读。

LSPosed 的在线模块库（`modules.lsposed.org`）由 [Xposed-Modules-Repo](https://github.com/Xposed-Modules-Repo) 组织托管。上架之后，用户可以在 LSPosed 客户端的「在线仓库」里搜到 Deskly，一键安装、自动更新。**不上架也完全可以正常用**，只是每次更新得手动下 APK 覆盖安装。

## 一、先解决包名

官方对包名有两套要求，二选一：

| 方案 | 要求 | 对 Deskly 的现状 |
|---|---|---|
| `io.github.<用户名>.*` | GitHub 组织成员身份需公开 | 当前包名是 `com.coby.deskly`，不符合 |
| 自持域名反写 | 域名根要有一条 TXT 记录：`lsposed-modules-repo-verification=<GitHub 用户名>` | 需要持有 `coby.com` 或等价域名 |

所以这台设备上装的包名直接提交会被机器人拒绝。两条路：

- **A（推荐，保留现有包名）**：如果手上有 `coby.com` 这类域名，加一条 TXT 记录即可；
- **B（改包名）**：把 `applicationId` 改成 `io.github.cobylinweiqi.deskly`，同时 `namespace` 可保持不变。代价是**已装用户的升级会中断**（签名相同但包名不同，系统视为两个应用），老用户需要手动备份 → 卸载 → 装新版 → 恢复。

改动落点：

```
app/build.gradle.kts        applicationId = "com.coby.deskly"
app/src/main/AndroidManifest.xml  （无显式包名，命名空间由 gradle 决定）
app/src/main/res/values/strings.xml  （无包名，不用改）
```

`scope.list` 与 `module.prop` 里不含包名，不用动。

## 二、提交

1. 打开 <https://modules.lsposed.org/submission/>（会跳到一个预填好的 Issue 页面）；
2. 标题填 `[submission] <包名>`，例如 `[submission] com.coby.deskly`；
3. 提交后机器人会为这个包名建一个仓库并邀请你成为管理员；
4. 在**那个仓库**里补上非空的 description（模块名）与 README；
5. 在**本项目**发布一个附带 APK 的 Release，tag 用 `<versionCode>-<versionName>`，例如 `18-0.12.2`。

之后每次发版：

```bash
# tag 必须带 versionCode，否则在线仓库不认
git tag 19-0.12.3
git push origin 19-0.12.3
gh release create 19-0.12.3 app/build/outputs/apk/release/app-release.apk \
  --title "0.12.3" --notes "更新说明"
```

机器人会在 5~15 分钟内索引到新版。

## 三、几个容易踩的点

- **只改 Release 里的 APK 不会触发更新**，必须新建一个 Release（或至少修改 Release 内容触发 webhook）；
- 仓库名必须等于包名，description 不能空，Release 里必须有 `.apk` 资产；
- 项目源码**留在本项目**，官方那个仓库只放摘要与 README，不放代码。
